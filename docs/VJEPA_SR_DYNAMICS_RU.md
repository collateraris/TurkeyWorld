## Обучение трёх режимов

Рабочий цикл переключён с шага 2512 на `three_mode`. В каждом обновлении AdamW 16 независимых окон по 180 шагов: 6 окон навигации без врага, 5 окон навигации с преследующим врагом без стрельбы и 5 окон боя. Цикл сохраняет LR `1e-5`, H180, обратную связь от замороженных Base/SR и 100 обновлений динамики за раунд. После переключения девятый раунд продолжает прежний счётчик; целое новое окно для каждой траектории начинается с четырёх наблюдённых состояний прошлого. Все 180 следующих действий прокручиваются на собственном прогнозе.

В боевом потоке размораживаются существующие выходы V-JEPA, предсказывающие цель выстрела и атаку врага. К ошибкам движения и латентного состояния добавляются классификация попадания при выстреле, классификация атаки на близкой дистанции и ошибка ожидаемого урона. Фактические события оригинала участвуют в расчёте ошибки. Скорость врага оценивается на продолжающейся жизни, чтобы телепортация при возрождении не становилась примером движения. Проверенные головы спокойной навигации и преследования заморожены. В `dynamics/metrics.jsonl` поля `streams.navigation`, `streams.enemy_motion` и `streams.combat` содержат отдельные результаты. `train_loss` после перехода включает боевое слагаемое.

На старте каждого нового мирового раунда сборщик создаёт 64 боевых TRAIN-эпизода по 360 тиков в `cycles/cycle_NNNNNN/combat_v1`. Боевой самплер использует 256 исходных длинных эпизодов, завершённые коллекции прошлых раундов и текущую. Тем самым в выборку входят промахи, попадания, урон игроку, гибель и возрождение. После блока динамики запускается отдельная проверка на 12 отложенных боевых окнах, сохраняемая в `cycles/cycle_NNNNNN/combat_validation.json`. Отчёт считает попадания в точный тик, ошибки HP, дрейф игрока и дрейф врага на сопоставимой жизни. Далее продолжаются существующие 50 обновлений actor–critic и сбор эпизодов политикой. Изменение боевого поведения политики оценивается отдельно от точности предсказаний мира.

## Непрерывный цикл

`run_vjepa_sr_cycle` не имеет лимита раундов:

1.100 обновлений динамики H180.
2.50 actor/critic updates в её замороженном prior; первоначально20 reward/continue warmup, после смены мира предусмотрена повторная калибровка.
3.64 NAV+64 quiet NPC эпизода Source по360 transitions, затем повтор.

Политика имеет148 входных признаков:state20+128D V-JEPA latent readout, но адаптер хранит полную память. Новая политика создаётся отдельно от RSSM policy; старые actor/critic сохранены. Реальный Source при сборе задаёт наблюдаемое state20; изображения для V-JEPA формируются Base/SR в том же домене. Инициализация/observe не сбрасывают всю историю каждый шаг. Imagination использует только собственный prior и SR, без Source feedback. Сбор маскируетfire, сохраняет quiet HP/alive, включает сложные wall cases и ограниченные64 попытки; исчерпание явно останавливает фазу ошибкой. Это ограничение попыток, не число раундов.

```bash
.venv-ubuntu/bin/python -m turkeyworld.run_vjepa_sr_cycle \
  --run-dir training_runs/vjepa_sr_cycle_20261117
```

Одновременно второй controller не запускать. Для остановки создать `training_runs/vjepa_sr_cycle_20261117/stop.request`: controller передаст запрос активной фазе и сохранит завершённый optimizer boundary. Для продолжения убрать пользовательские stop flags после проверки статуса; checkpoints, Adam, samplers/RNG и round/phase продолжаются. Цикл не запускает GUI.

### Как проверить, что ограничитель движения мешает обучению

Сравнивайте две копии **одного** training checkpoint, включая Adam и sampler, с неизменными коллекциями replay. Для каждой копии путь к весам внутри отдельной рабочей папки — `checkpoints/vjepa_world.pt`. Не копируйте веса в каталог запущенной игры или тренера. В каждой папке запустите из корня репозитория:

```bash
python -m turkeyworld.train_vjepa_sr_dynamics --run-dir "$BRANCH" --until-updates "$TARGET" --player-clamp-gradient "$MODE" --wall-weight .25
python -m turkeyworld.validate_vjepa_sr --world "$BRANCH/checkpoints/vjepa_world.pt" --panel independent --output "$BRANCH/validation.json" --auxiliary-mode blocks16 --wall-weight .25
```

`MODE` принимает `hard` для контроля и `ste` для эксперимента. `TARGET` — абсолютный счётчик `vjepa_sr_training.updates` исходного снимка плюс четыре, не номер глобального шага. Пример для снимка 2315: 682 + 4 = 686. Обе ветки используют H180, MAIN16 и LR 1e-5. До сравнения проверьте совпадение списков `samples` в metrics.jsonl, номеров шагов и отпечатка панели. В этом опыте обычное продолжающееся обучение уже дало контрольные обновления, поэтому их не нужно повторять.

На независимой панели нет эпизодов из прежнего фиксированного VAL-набора. Дрейф и пересечения стен измеряются замкнутым H180 без будущего Source. Ложные остановки измеряются отдельно: каждые 16 шагов даём обеим моделям один и тот же истинный четырёхкадровый контекст и одну команду. Ось считается свободной при фактическом проходе ≥75% команды, заблокированной при ≤25%. Ложная остановка — прогноз ≤25% на свободной оси; ложный проход — прогноз ≥75% на заблокированной. Промежуточные случаи не входят в эти две доли.

Для проверки погони на закреплённом снимке:

```bash
python -m turkeyworld.audit_vjepa_npc_target --world "$SNAPSHOT" --output "$OUT/npc_target.json"
```

Только в диагностической половине парного прогона XY игрока после перехода заменяются истинными; следующие состояние памяти и обратная связь от SR учитывают это положение. Состояние врага всегда предсказывает модель. Сравниваются одни и те же восемь окон преследования; это не метрика автономного качества для исправленной половины.

Для отдельного опыта с движением врага `python -m turkeyworld.pilot_npc_direction --world "$SNAPSHOT" --out "$OUT/npc_direction"` обучает небольшую сеть на CPU, на 64 эпизодах TRAIN, а затем сравнивает её с V-JEPA и переносом прежней скорости на одинаковых стартах из VAL. Сеть видит занятость 5×5 клеток вокруг врага, его положение внутри клетки, скорость и смещение до игрока. Её собственный оптимизатор не связан с LR основной V-JEPA. Отчёт по одному шагу не доказывает снижения дрейфа: дополнительно сравнивайте H180 и пересечения стен на собственной траектории врага.

### Обучаемое движение по осям в навигации без врага

В режиме `learned_axis_collision_nav` V-JEPA берёт скорость и направление шага из команды. Отдельный модуль динамики учится решать, пройдёт ли игрок сначала по X, затем по Y из полученной позиции. Он видит собственные координаты игрока и занятость ближайших 3×3 клеток известной карты. Чтобы одну границу не приходилось заново изучать при повороте карты, одни и те же веса оценивают признаки положения относительно каждой занятой клетки с учётом симметрии осей. Это линейный классификатор на восьми геометрических признаках с одним смещением: девять обученных чисел. Радиус игрока и функция столкновения оригинала на вход ему не передаются. Во время игры и в H180 оригинал не проверяет и не поправляет координаты прогноза. При включённом противнике режим использует прежний прогноз смещения.

Чтобы повторить обучение из корня проекта, укажите неизменяемый полный снимок V-JEPA 30 Гц с режимом движения `delta` в `BASE`, новую папку для эксперимента в `RUN`. Исходные TRAIN-коллекции NAV и quiet и замороженные файлы Base/SR должны находиться по путям проекта.

```bash
mkdir -p "$RUN"
python -m turkeyworld.validate_nav_contacts --manifest "$RUN/hard_manifest.json"
python -m turkeyworld.train_local_axis_collision --base "$BASE" --out "$RUN" --steps 10000 --batch 320
for arm in base candidate; do
    world="$BASE"
    if [ "$arm" = candidate ]; then world="$RUN/candidate.pt"; fi
    for panel in fixed independent; do
        python -m turkeyworld.validate_vjepa_sr --world "$world" --panel "$panel" --auxiliary-mode blocks16 --wall-weight .25 --output "$RUN/${arm}_${panel}.json"
    done
    python -m turkeyworld.validate_nav_contacts --world "$world" --manifest "$RUN/hard_manifest.json" --output "$RUN/${arm}_hard.json"
done
python -m turkeyworld.qualify_local_axis_navigation "$RUN"
```

Аугментация охватывает проход вдоль стены, блокировку, движение у углов, а также положения, в которые попадает сама обучаемая голова. Правило столкновений оригинала даёт только метки для TRAIN. Оптимизатор головы — отдельный AdamW с LR `1e-5`; исходный оптимизатор основной модели и его счётчики не расходуются. В обычном цикле проверенная голова заморожена. Для финальной копии с прежним поведением в преследовании используйте `python -m turkeyworld.attach_local_axis_head --base "$BASE" --validated "$RUN/candidate.pt" --trained "$RUN/head.pt" --nav-only --output "$RUN/nav_only.pt"`. Записывайте в новый файл: запуск этой команды не меняет активный checkpoint.

## Движение игрока и одного преследователя без боя

В режиме `learned_axis_quiet_pair` V-JEPA получает карту 16×16, собственное состояние и текущую команду. Сначала модель предсказывает смещение игрока. Она проверяет X и затем Y у ближайших стен. Положение после X участвует в проверке Y. У игрока и у врага свои обученные границы контакта, включая скольжение около внешнего угла стены.

Цель преследователя на текущем тике — уже предсказанная позиция игрока. Модуль выбирает прямое движение или направление к соседней клетке. Геометрия маршрутизации задана в архитектуре. Стоимость прохода распространяется по четырём соседям за 32 итерации. Стоимости клеток, предпочтения при равных путях, видимость цели, скорость, остановка и контакт подогнаны по обучающей карте. Для обучения использованы 64 исходные погони и дополнительные метки движка на TRAIN. В автономном прогнозе будущие координаты оригинала и его поиск пути не используются.

Пара включается, когда оба персонажа живы, отсутствуют выстрел и активные боевые таймеры, а дистанция в начале тика исключает ближний удар после перемещения игрока. У самой границы удара возможен переход к прежней динамике даже при отпущенной кнопке огня. Оба новых модуля заморожены в основном цикле. V-JEPA продолжает обучение со своим Adam и обратной связью от Base/SR. Проверка охватывает игровую карту проекта при 30 Гц.

### Воспроизведение

Запустите команды из корня проекта в его Python-окружении. В `BASE` укажите сохранённый V-JEPA с режимом `learned_axis_collision_nav` из предыдущего раздела, в `RUN` — новый каталог. Для расчёта H180 потребуется CUDA. Подготовьте неизменяемые стартовые ленты перед обучением.

```bash
mkdir -p "$RUN"
python -m turkeyworld.validate_quiet_pursuit --panel-dir "$RUN/panel"
python -m turkeyworld.validate_quiet_pursuit --panel-dir "$RUN/holdout" --seed 645912043
python -m turkeyworld.train_quiet_player_contact --out "$RUN"
python -m turkeyworld.train_quiet_pursuit --out "$RUN" --steps 12000
python -m turkeyworld.refine_quiet_npc_contact --parent "$RUN/pursuit_head.pt" --out "$RUN/refined"
python -m turkeyworld.attach_quiet_pair --base "$BASE" --player "$RUN/quiet_player_head.pt" \
    --npc "$RUN/refined/pursuit_head.pt" --output "$RUN/candidate.pt"

for arm in base candidate; do
    world="$BASE"
    if [ "$arm" = candidate ]; then world="$RUN/candidate.pt"; fi
    for panel in fixed independent; do
        python -m turkeyworld.validate_vjepa_sr --world "$world" --panel "$panel" \
            --auxiliary-mode blocks16 --wall-weight .25 --output "$RUN/${arm}_${panel}.json"
    done
    python -m turkeyworld.validate_quiet_pursuit --world "$world" \
        --panel-dir "$RUN/panel" --output "$RUN/${arm}_hard_quiet.json"
    python -m turkeyworld.validate_quiet_pursuit --world "$world" --seed 645912043 \
        --panel-dir "$RUN/holdout" --output "$RUN/holdout/${arm}_hard_quiet.json"
done
python -m turkeyworld.qualify_quiet_pair "$RUN" --holdout "$RUN/holdout" --output "$RUN/qualification.json"
```

Первые две проверки используют по восемь отложенных погонь и по восемь окон навигации. На каждой из двух дополнительных панелей — 24 погони: поворот за препятствием, стрейф лицом к врагу и смена дистанции. Отчёты содержат ошибки на шагах 16, 48, 112 и 180 в клетках, среднюю ошибку вдоль траектории и число тиков пересечения стены. Для врага поле `npc_wall_ticks_engine_radius` использует игровой радиус 0,25 клетки. У шести архивных видеонарезок свои ленты, и они оцениваются отдельно.
